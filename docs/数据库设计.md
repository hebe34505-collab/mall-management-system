# 数据库设计

数据库名：`mall_db`，字符集 `utf8mb4`。脚本在 `database/schema.sql` 和 `database/seed.sql`。

## 关系

```text
users 1 --- n addresses
users 1 --- n cart_items n --- 1 products
users 1 --- n orders 1 --- n order_items
categories 1 --- n products
products 1 --- n stock_logs
users 1 --- n operation_logs
```

`order_items` 保存下单时的商品名称、图片、单价和数量，不建立到 `products` 的外键。商品删除后，历史订单仍然可以查看。

购物车通过唯一索引 `(user_id, product_id)` 防止同一用户重复添加同一商品。用户名和邮箱分别有唯一索引。

## 表说明

| 表 | 作用 |
| --- | --- |
| users | 账户、BCrypt 密码、角色、启用状态、令牌版本 |
| categories | 商品分类 |
| products | 商品价格、库存、销量、上下架、是否推荐 |
| cart_items | 当前用户的购物车 |
| addresses | 收货地址 |
| orders | 订单主表，金额由后端计算 |
| order_items | 订单商品快照 |
| stock_logs | 下单扣减、取消回滚、管理员调整 |
| operation_logs | 登录、商品、订单、用户状态等操作记录 |

## 状态

- 用户 `status`：1 启用，0 禁用。
- 商品 `status`：`ON_SHELF` 上架，`OFF_SHELF` 下架。
- 订单 `status`：
  - `PENDING_SHIPMENT` 待发货，可取消，计入销售额
  - `SHIPPED` 已发货，管理员可完成，计入销售额
  - `COMPLETED` 已完成，计入销售额
  - `CANCELLED` 已取消，不计入销售额，库存回滚

订单状态只能按上面的方向变化。已完成和已取消不能再改。

## 并发扣库存

下单事务中先按商品编号排序，再 `SELECT ... FOR UPDATE` 锁定商品行，然后执行：

```sql
UPDATE products
   SET stock = stock - ?, sales = sales + ?
 WHERE id = ? AND status = 'ON_SHELF' AND stock >= ?
```

更新行数不是 1 时，事务回滚。取消订单时按相反方向回滚库存，并写库存流水。
